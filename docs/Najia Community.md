# 1. EXECUTIVE SUMMARY

## 1.1 Platform Overview

Najia Community Bridge is a civic technology platform designed to strengthen the relationship between Nigerian citizens and their government while providing access to legal resources and verified evidence management. The platform operates on three interconnected pillars: citizen engagement with governance, evidence integrity and verification, and access to legal representation.

The platform serves as a non-binding, transparent bridge between citizens and institutions, enabling structured feedback on government policies, confidence measurement in elected officials, secure evidence handling for disputes, and connection to qualified legal professionals. All activities are conducted within clear legal and ethical boundaries, with robust safeguards against manipulation, misuse, and misinterpretation.

## 1.2 Core Mission

To empower Nigerian citizens with tools for informed civic participation, verified evidence management, and access to justice, while maintaining the highest standards of integrity, transparency, and legal compliance.

## 1.3 Value Proposition

| Stakeholder         | Value Provided                                                          |
| ------------------- | ----------------------------------------------------------------------- |
| Citizens            | Voice in governance, evidence security, legal access, civic education   |
| Government          | Real-time citizen sentiment data, structured feedback, reduced distrust |
| Legal Professionals | Client acquisition, pro bono opportunities, professional visibility     |
| Civil Society       | Data for advocacy, citizen engagement tools, accountability monitoring  |
| Investors/Donors    | Social impact, measurable outcomes, sustainable model                   |

## 3.1 Policy Sentiment Polls

### 3.1.1 Overview

Policy sentiment polls allow citizens to express their views on government initiatives, proposed legislation, and policy directions. These are non-binding expressions of public sentiment designed to inform policymakers and increase citizen participation in governance.

### 3.1.2 Purpose

- Gauge public sentiment on government policies and initiatives
- Provide structured feedback to policymakers
- Increase citizen engagement in governance
- Create a record of public opinion over time
- Identify areas of consensus and concern

### 3.1.3 Scope and Levels

| Level    | Description                                    | Jurisdiction          |
| -------- | ---------------------------------------------- | --------------------- |
| National | Federal government policies and initiatives    | National              |
| State    | State government policies and programs         | State-specific        |
| Local    | Local government policies and community issues | Local government area |

### 3.1.4 Poll Format

| Element  | Description                                           |
| -------- | ----------------------------------------------------- |
| Title    | Clear, concise policy topic                           |
| Summary  | Plain-language explanation of the policy or issue     |
| Question | Specific, measurable question aligned with the policy |
| Options  | Binary, multi-choice, or scale-based responses        |
| Context  | Links to official policy documents where available    |

| Requirement  | Description                                |
| ------------ | ------------------------------------------ |
| Verification | Voter must be ID-verified (NIMC or Onfido) |
| Uniqueness   | One vote per person per poll               |

| Element               | Description                                                            |

- Emergency polls: Crisis response (moderator discretion)

## 3.3 Critical Safeguards for Civic Features

### 3.3.1 Perception and Communication Risks

| Risk                        | Mitigation                                                                                                                              |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Perception of binding votes | Prominent disclaimers on all poll and confidence vote materials: "This is citizen sentiment only. It has no legal or electoral weight." |
| Political weaponization     | Strict poll creation controls; published methodology; non-partisan language                                                             |
| Government backlash         | Non-binding framing; operational independence; legal counsel review                                                                     |
| Misleading questions        | Polls drafted by platform; reviewed by advisory board; public comment period                                                            |
| Regulatory exposure         | Legal counsel review; compliance with election-related regulations; clear distinction from official processes                           |

### 3.3.2 Manipulation and Integrity Risks

| Risk                    | Mitigation                                                              |
| ----------------------- | ----------------------------------------------------------------------- |
| Voter manipulation      | NIMC/Onfido verification; one vote per person per poll                  |
| Bot attacks             | CAPTCHA on voting; rate limiting; IP monitoring                         |
| Vote buying/selling     | Individual vote verification; no financial incentives for voting        |
| Reputation manipulation | **No reputation weighting on civic votes** — strict one-person-one-vote |
| Duplicate voting        | Database uniqueness constraints; identity verification                  |

### 3.3.3 Polarization Risks

| Risk                    | Mitigation                                                                   |
| ----------------------- | ---------------------------------------------------------------------------- |
| Social polarization     | Results shown with confidence intervals; avoid ranking leaders               |
| Harassment of officials | Focus on policy, not personal attacks; moderation of comments                |
| Regional divisions      | Only show regional breakdowns with sufficient data; emphasize national unity |
| Echo chambers           | Show diverse perspectives; present context and background                    |

# 4. EVIDENCE INTEGRITY & DEEPFAKE DETECTION

## 4.1 Overview

The evidence integrity system addresses two distinct but complementary concerns:

1. **Chain-of-custody integrity** — ensuring uploaded files remain untampered
2. **AI-manipulation detection** — identifying synthetically generated or altered media

These are handled separately because they serve different purposes, use different technologies, and carry different implications for users.

---

## 4.2 Evidence Integrity Pipeline

### 4.2.1 Purpose

Guarantee that uploaded evidence has not been silently altered after upload, maintaining a verifiable chain of custody.

### 4.2.2 Method

| Step            | Description                                          |
| --------------- | ---------------------------------------------------- |
| Upload          | User uploads evidence file through web or mobile app |
| Hash Generation | SHA-256 cryptographic hash computed from the file    |
| Timestamp       | Append-only timestamp record created                 |
| Storage         | File stored securely with hash and metadata          |
| Verification    | Re-hash and compare on every access                  |
| Audit Trail     | All access events logged                             |

### 4.2.3 Scope

All evidence types are covered:

- Images (JPG, PNG, WebP)
- Video (MP4, AVI, WebM)
- Audio (MP3, WAV, M4A)
- Documents (PDF, DOCX, TXT)

### 4.2.4 Verification Display

| Indicator      | Description                                      |
| -------------- | ------------------------------------------------ |
| Green Badge    | Verified: File matches original upload           |
| Red Warning    | Not Verified: File has been altered since upload |
| Pending        | Verification in progress                         |
| Not Applicable | File type doesn't support hash verification      |

---

## 4.3 AI-Powered Manipulation Detection

### 4.3.1 Purpose

Flag plausible AI-generated or manipulated media as an input to human review, not as a definitive verdict.

### 4.3.2 Scope

| Media Type | Detection Applied | Notes                                                                                            |
| ---------- | ----------------- | ------------------------------------------------------------------------------------------------ |
| Images     | Yes               | Primary detection focus                                                                          |
| Videos     | Yes               | Multiple detection methods combined                                                              |
| Audio Only | No                | Audio deepfakes are a real risk, but out of scope initially due to detection complexity and cost |
| Documents  | No                | Manipulation assessed through hash only                                                          |

### 4.3.3 Detection Methods

| Method                         | Description                                               | Applicable Media |
| ------------------------------ | --------------------------------------------------------- | ---------------- |
| Metadata Analysis              | Examine file metadata for generation artifacts            | Images, Videos   |
| Visual Artifact Detection      | Detect pixel-level anomalies, compression patterns        | Images           |
| Audio-Video Sync Analysis      | Check lip sync and audio coherence                        | Videos           |
| Facial Inconsistency Detection | Identify inconsistent facial features, blending artifacts | Images, Videos   |
| Generation Watermarks          | Detect generation-time watermarks (limited coverage)      | Images, Videos   |

### 4.3.4 Detection Output

| Output Type             | Description                                           |
| ----------------------- | ----------------------------------------------------- |
| Confidence Score        | Float value indicating likelihood of manipulation     |
| Category                | Low (0–33%), Medium (34–66%), High (67–100%)          |
| Detection Model Version | Which model and thresholds scored this file           |
| Applicability Flag      | Whether AI detection was attempted for this file type |

### 4.3.5 Display to Users

| Display Element     | Description                                                |
| ------------------- | ---------------------------------------------------------- |
| Integrity Status    | "This file passed/failed integrity checks"                 |
| AI Detection Status | "This file was/was not flagged for AI manipulation"        |
| User Guidance       | "Users should independently evaluate authenticity"         |
| Confidence Level    | Low / Medium / High (with explanatory text)                |
| Disclaimer          | "This is an automated detection, not a definitive verdict" |

### 4.3.6 Human Review Process

| Step             | Description                                        |
| ---------------- | -------------------------------------------------- |
| Auto-Flag        | High-confidence detections automatically flagged   |
| Moderator Review | Flagged content reviewed by trained moderators     |
| Escalation       | Ambiguous cases escalated to specialized reviewers |
| User Appeal      | User can request human re-review                   |
| Final Status     | Status updated based on human review               |

### 4.3.7 Known Limitations

| Limitation                                    | Communication                                                                             |
| --------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Detectors tuned for synthetic faces/deepfakes | Most civil-dispute evidence (property damage, receipts, chat screenshots) is not in-scope |
| False positives possible                      | Users are informed of detection limitations                                               |
| False negatives possible                      | Users are encouraged to independently verify                                              |
| No detection is perfect                       | Clear communication of probabilistic nature                                               |
| Coverage limited to certain media types       | Audio, documents, and some image formats may not be analyzed                              |

---

## 4.4 Detection Pipeline Flow

| Stage | Process                                                                                  |
| ----- | ---------------------------------------------------------------------------------------- |
| 1     | User uploads evidence                                                                    |
| 2     | Hash + timestamp generated (integrity)                                                   |
| 3     | File type checked                                                                        |
| 4a    | If not image/video: skip AI detection; integrity-only verification                       |
| 4b    | If image/video: proceed to AI detection                                                  |
| 5     | Metadata analysis performed                                                              |
| 6     | Visual artifact detection performed                                                      |
| 7     | Audio-video sync analysis performed (video only)                                         |
| 8     | Ensemble score calculated                                                                |
| 9     | Category assigned: Low (green), Medium (yellow, flagged), High (red, moderator required) |
| 10    | Results stored and displayed                                                             |

# 5. LAWYER MATCHING & CASE REFERRAL

## 5.1 Overview

The Lawyer Marketplace connects citizens with verified legal professionals for advice, representation, and case management. The platform facilitates initial consultation, matching, and engagement while maintaining clear separation between platform services and legal services.

---

## 5.2 Lawyer Marketplace Features

### 5.2.1 Purpose

- Connect citizens with qualified legal representation
- Increase access to justice
- Provide transparent information about legal services
- Enable informed choice of legal counsel

### 5.2.2 Lawyer Role

| Aspect         | Description                                  |
| -------------- | -------------------------------------------- |
| Status         | Independent professionals, platform-verified |
| Engagement     | Contract with client, not with platform      |
| Fees           | Set by lawyers, transparently displayed      |
| Specialization | Various practice areas displayed             |
| Pro Bono       | Encouraged and highlighted                   |

### 5.2.3 Fee Structure

| Element           | Description                                                                                                                                                |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Lawyer Fees       | Set by lawyers; transparently displayed                                                                                                                    |
| Platform Fee      | Flat matching/subscription fee model                                                                                                                       |
| Prohibited Model  | **Platform must NOT take a percentage of legal fees** — this could be characterized as fee-splitting with non-lawyers, which is restricted under bar rules |
| Recommended Model | Flat listing fee or flat matching fee, invoiced separately from legal fees                                                                                 |

> **Critical Note:** The fee model must be reviewed by legal counsel and bar association guidance before implementation. A percentage cut of lawyer fees is prohibited in most jurisdictions as fee-splitting with non-lawyers. (This constraint is why the Prohibited Revenue list in §10.1.2 rules out any fee tied to legal-fee percentage, and why §5.6.1 flags fee-splitting as a standing operational risk.)

# 6. IDENTITY VERIFICATION

## 6.1 Overview

Identity verification is a critical component of the platform, ensuring that each citizen has a unique, verified identity. The platform uses a two-tier verification system with NIMC NVS API as the primary method and Onfido as a fallback.

## 6.2 NIMC NVS API Integration

### 6.2.1 Overview

The National Identity Management Commission (NIMC) National Verification Service (NVS) API is the primary identity verification method for citizens. It provides government-recognized verification through Nigeria's national identity database.

### 6.2.2 Verification Flow

| Step | Process                                                                         |
| ---- | ------------------------------------------------------------------------------- |
| 1    | User submits National Identification Number (NIN), Date of Birth, and Full Name |
| 2    | Platform validates NIN format (11-digit number)                                 |
| 3    | Platform sends request to NIMC NVS API                                          |
| 4    | NIMC NVS API verifies identity against national database                        |
| 5a   | Match Found: verification successful, user profile updated                      |
| 5b   | No Match: verification failed, Onfido fallback initiated                        |

### 6.2.3 NIMC NVS API Specifications

| Element             | Specification                         |
| ------------------- | ------------------------------------- |
| **API Version**     | NIMC NVS v2.0                         |
| **Authentication**  | Client ID + Client Secret + Timestamp |
| **Request Format**  | JSON over HTTPS                       |
| **Response Format** | JSON                                  |
| **Timeout**         | 10 seconds                            |
| **Retry Policy**    | 3 retries with exponential backoff    |
| **Cache TTL**       | 30 days (non-sensitive data)          |

## 6.3 Onfido Integration

### 6.3.1 Overview

Onfido serves as a secondary/fallback verification method when NIMC verification fails or for users who do not have a NIN. It provides document-based identity verification.

### 6.3.2 Onfido Verification Flow

| Step | Process                                                                      |
| ---- | ---------------------------------------------------------------------------- |
| 1    | User submits government-issued ID (Passport, Driver's License, Voter's Card) |
| 2    | User submits selfie for facial comparison                                    |
| 3    | Platform uploads documents to Onfido                                         |
| 4    | Onfido processes verification                                                |
| 5a   | Verification Clear: user verified                                            |
| 5b   | Verification Failed: manual review initiated                                 |

### 6.3.3 Onfido Webhook Events

| Event              | Description                   | Action                   |
| ------------------ | ----------------------------- | ------------------------ |
| `check.completed`  | Verification check completed  | Update user status       |
| `check.failed`     | Verification check failed     | Notify user, allow retry |
| `report.completed` | Verification report generated | Process results          |

## 6.4 Verification Strategy

### 6.4.1 Verification Priority

| Level   | Method              | Description                                                                    |
| ------- | ------------------- | ------------------------------------------------------------------------------ |
| Level 1 | NIMC NVS API        | Primary verification method, government-recognized, preferred for all citizens |
| Level 2 | Onfido (Fallback)   | Secondary verification for users without NIN or NIMC verification failures     |
| Level 3 | Manual Verification | For edge cases, verification appeals, staff-assisted verification              |

### 6.4.2 Verification States

| State                     | Description                                         |
| ------------------------- | --------------------------------------------------- |
| UNVERIFIED                | User has not completed verification                 |
| NIMC VERIFICATION PENDING | NIMC verification in progress                       |
| NIMC VERIFIED             | User verified through NIMC                          |
| NIMC FAILED               | NIMC verification failed, Onfido fallback initiated |
| ONFIDO PENDING            | Onfido verification in progress                     |
| ONFIDO VERIFIED           | User verified through Onfido                        |
| ONFIDO FAILED             | Onfido verification failed, manual review initiated |
| MANUAL REVIEW             | Verification under manual review                    |
| VERIFIED                  | User fully verified                                 |
| REJECTED                  | Verification rejected                               |

# 8. MODERATION & CONTENT GOVERNANCE

## 8.1 Moderation Overview

The platform maintains content integrity through a multi-tiered moderation system that combines automated detection with human review.

### 8.1.1 Moderation Principles

- **Transparency:** All moderation actions are documented and visible to affected users
- **Appeal:** Users can appeal moderation decisions
- **Consistency:** Clear guidelines applied uniformly
- **Proportionality:** Actions match severity of violations
- **Human Review:** Automated actions are reviewed by humans

# 18. CONCLUSION

## 18.1 Platform Summary

Najia Community Bridge is a comprehensive civic technology platform designed to:

1. **Strengthen citizen engagement** through non-binding policy polls and confidence votes
2. **Maintain evidence integrity** through cryptographic verification and AI-assisted detection
3. **Improve access to justice** through lawyer matching and case referral
4. **Uphold ethical standards** through transparent governance and robust safeguards
5. **Ensure sustainability** through diversified revenue and impact measurement
6. **Educate and inform** through blog content and legal literacy modules
7. **Verify identity** through NIMC NVS API and Onfido integration
